项目简介

颜文字（Kaomoji）是一类纯文本的表情符号。它的问题是：好看的组合往往记不住，而随手敲的又经常歪。

本项目解决的就是这一步：把「我想要什么」翻译成一组可直接粘贴的成品，并且保证这些成品在等宽环境下排版不歪、字符在主流设备上都能正常显示。

核心价值主张

  • 确定性优先：颜文字永远由工具产出，不是模型写的。输出可校验、可复现、可回退。
  • 零模型可用：AI 是可选开关，默认关闭；关闭时全流程零模型调用。
  • 宽度优先排版：所有对齐都走真实的显示列宽，而不是 str.length。
  • 零第三方运行时依赖：除 React 外全部手写，构建产物 gzip 后约 60 KB。

与同类做法的差异

维度常见做法本项目
内容来源让模型直接「写」颜文字模型只输出结构化意图，颜文字由成品库 / 拼装 / 栅格化产出
排版基准str.length 或目测displayWidth()（EAW + 组合字符 + VS16）
质量兜底无统一走校验器（宽度 / 括号 / 行数 / 字符安全）
可复现性每次结果不同组件拼装用种子伪随机，同样输入必得同样输出

架构全景

一条流水线，五个环节，三条并行的生成策略。模型只出现在「意图解析」且是可选的，其余环节全是确定性工具。

核心方法

① 显示宽度：一切排版的地基

中文占 2 列、组合记号占 0 列、VS16 会把字符从 1 列升级为 2 列。用 str.length 排版，一歪就是歪一片。

src/core/width.ts
(˘̩̩̩ε˘̩ƪ).length        // 13  ← 无意义
displayWidth('(˘̩̩̩ε˘̩ƪ)')  // 9   ← 真实列宽
displayWidth('好')          // 2
displayWidth('⚈')          // 1

② 组件拼装：语法 + 硬约束

零件按情绪打标签，按固定语法拼装。生成后不满足约束就丢弃重来。

src/core/compose.ts —— 语法
[装饰] [左臂] [左括号] [腮红] 左眼 [嘴]
        右眼 [腮红] [右括号] [右臂] [装饰]

约束 1  括号必须配对
约束 2  左右眼宽度差 <= 2
约束 3  手臂左右成对且等宽

③ 字形栅格化：两个坑

坑一 · 均值映射会把细笔画吃掉

一格中只有 30% 面积是笔画时，平均亮度会掉到接近空白。改用覆盖率（超过阈值的像素占比）配 gamma 提升对比度，笔画才立得起来。

坑二 · 字符格宽高比是 1:2

纵向分辨率天然只有横向一半，「喜」的七道横画会糊在一起。解法是半格块 ▀▄█：一个字符格编码上下两个像素，纵向分辨率翻倍。

代价：▀▄█ 的 East Asian Width 是 Ambiguous，部分中文环境会按 2 列渲染导致横向拉伸。因此默认输出走 symbol 风格（纯窄字符），block 作为可选并在卡片上标注风险。

终端

使用示例

调用生成流水线

src/core/pipeline.ts
import { generate } from './core/pipeline'

const { intent, candidates, notes } = await generate(
  '今天有点委屈，像被雨淋湿的小狗',
  {
    kind: 'auto',   // 自动判断：颜文字 / 组合 / 拼字 / 图案
    count: 6,
    useAI: false,   // 关闭时全流程零模型调用
  },
)

intent      // 结构化意图：类型 / 情绪 / 主体 / 动作
candidates  // 已通过校验的候选，每条都可直接复制
notes       // 回退与提示信息

用列宽而不是字符串长度

src/core/width.ts
import { displayWidth, maxLineWidth, isVisuallyBalanced } from './core/width'

maxLineWidth(art)          // 多行作品的最大列宽
isVisuallyBalanced(art)    // 多行是否视觉居中（容差按列宽算）

校验一件作品

src/core/validator.ts
import { validate, hasError } from './core/validator'

const issues = validate(art, {
  maxLines: 1,
  maxWidth: 64,
  requireBalancedBrackets: true,
})

if (hasError(issues)) {
  // 有 error 级问题：丢弃这件作品
}

质量保障

校验器覆盖的检查项

  • 字符安全：控制字符（error）、私有使用区（error）、冷门文字区（warn）
  • 宽度：单行最大列宽、多行是否等宽或视觉居中
  • 结构：括号配对（用栈检查，支持嵌套）
  • 行数：按作品类型分别设上限
  • 细节：行尾空白提醒

这套闸门也是把 AI 的自由输出关进确定性笼子的手段 —— 模型只出 JSON，产物永远过校验。

工程约束

  • TypeScript strict + noUnusedLocals + noUnusedParameters
  • 构建即类型检查：tsc --noEmit && vite build
  • 无测试框架；以类型系统 + 校验器作为质量基线
  • 组件拼装用种子伪随机，保证「同样输入 → 同样输出」

贡献指南

最容易参与的贡献是扩充词库，改动集中在 src/data/。

  • 成品库 kaomoji.ts：必须带情绪标签；只使用主流设备都有字形的字符
  • 组件库 parts.ts：零件带情绪标签；手臂左右成对且等宽
  • 提交信息遵循 Conventional Commits（feat: / fix: / docs: …）
  • 提 PR 前确认 npm run build 通过
